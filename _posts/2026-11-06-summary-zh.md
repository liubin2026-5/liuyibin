### [全面节约方案部署电池循环，回收与制造衔接待解](https://www.cyzone.cn/article/853154.html) ⭐️ 7.0/10

11 月 4 日公开的《实施全面节约战略行动方案》提出构建新能源汽车动力电池全生命周期管理体系，并推动汽车、家电、日化行业再生材料应用升级。政策重心从废弃物处置转向再生资源回流生产线，对电池产业链提出溯源清晰、处理适配、材料可再利用三项核心要求。受影响人群包括电池回收、再生材料及产业链数据协同从业者。

**「内容切入角度」** 可做角度：从政策提出的“溯源清晰、处理适配、材料可再利用”三项要求出发，结合退役电池原料规格差异大、物料交接易信息断档的现实，分析回收与制造衔接中物料信息同步和材料质量匹配的具体难点，避免将企业数量直接等同于处理能力。

### [Claude Code 被指将用户邮箱发送至外部网站](https://github.com/anthropics/claude-code/issues/107757) ⭐️ 8.0/10

GitHub 上 Anthropic 的 claude-code 仓库出现一个 issue（\#107757），报告 Claude Code 会把用户的邮箱地址发送给外部网站，该 issue 随后在 Hacker News 引发讨论（1137 分、347 条评论）。社区评论指出，许多案例集中出现在调用 SEC API 时，而 SEC API 文档要求请求的 User-Agent 中包含邮箱，否则会拒绝请求，因此这一行为至少部分源于第三方 API 的要求，而非 Anthropic 的刻意设计。讨论由此延伸到 AI 编码代理的沙箱隔离、对用户数据的访问权限以及网络请求日志透明度等问题。目前证据主要来自社区报告，根本原因尚未由官方完整说明。

hackernews · motoroco · 11月5日 22:17 · [社区讨论](https://news.ycombinator.com/item?id=50385272)

**「背景」** Claude Code 是 Anthropic 推出的命令行 AI 编码代理，可在本地项目中执行命令并访问网络。SEC 的 data.sec.gov 接口要求调用方在 User-Agent 中提供邮箱作为身份标识，否则返回错误，这使得代理在访问该接口时可能自动带上用户邮箱。

**「影响」** 使用 Claude Code 访问 SEC API 等要求身份标识的服务的开发者，其邮箱可能被发送给第三方网站，并可能因此收到针对性垃圾邮件；评论中已有用户报告工作邮箱垃圾邮件增多，但因果关系尚未得到证实。

**「社区讨论」** 评论者普遍认为 Claude 不应在未经明确许可的情况下访问用户信息、沙箱外文件或网络，并呼吁对每个请求保留完整日志；有人列举了此前多个相关 issue，也有用户怀疑自己的垃圾邮件与使用 Claude 有关。另一些评论则指出，SEC API 强制要求 User-Agent 含邮箱，是理解该现象的关键背景。

### [OpenSSH 密码认证绕过与 crypt\(\) 哈希处理](https://sshhole.com/) ⭐️ 8.0/10

Hacker News 上讨论了一起与 crypt\(\) 哈希处理相关的 OpenSSH 密码认证绕过问题。攻击者的目标是让 sshd 在验证时满足 crypt\($pw, $hash\) 的返回值等于 $hash，从而通过密码校验。问题出在 $hash 通常形如“$6$--gibberish”，但对不允许登录的账户可能是“\*”或“\!”这类特殊值，而 crypt\(\) 对这类输入的处理方式导致了绕过。讨论还涉及 musl libc 的相关行为：musl 此前已针对 crypt\_des 中的同类失败做过规避，但未在 crypt\_sha 路径上做同样处理，因此该路径仍受影响。相关链接指向 OpenSSH 10.6p2 发布说明和 Alpine Linux 的安全公告。

hackernews · josemrb · 11月5日 12:19 · [社区讨论](https://news.ycombinator.com/item?id=50378228)

**「背景」** OpenSSH 的 sshd 使用系统 crypt\(\) 函数校验用户密码：它把用户输入的密码和 /etc/shadow 中保存的哈希作为参数传给 crypt\(\)，再比较返回值与存储的哈希是否一致。在传统 Unix 密码文件中，“\*”或“\!”等字符串被用作占位符，表示该账户没有可用密码、不应允许密码登录。crypt\(\) 本身也使用特殊返回值表示哈希计算失败，这种用同一字符串同时表达“无密码”和“计算出错”的做法，正是此次问题的根源之一。

**「影响」** 使用受影响 OpenSSH 版本和 libc 组合的系统可能允许攻击者绕过密码认证，尤其是账户哈希被设为“\*”或“\!”等占位符、本应禁止密码登录的场景。

**「社区讨论」** 评论者普遍认为根因是“带内信号”式设计：用“\*”同时表示“无密码”和“哈希出错”并不可靠，有人主张应返回明确的失败值或结果类型，而不是魔法字符串。也有评论指出 musl 已在 crypt\_des 中规避同类问题，但遗漏了 crypt\_sha 路径，使漏洞面比表面看起来更广。

**标签**: `#security`, `#openssh`, `#authentication`, `#crypt`, `#open-source`

### [Inkling 2 Small：全 nvfp4 训练的开源权重模型](https://thinkingmachines.ai/news/inkling-2-small/) ⭐️ 7.0/10

Thinking Machines 发布开源权重模型 Inkling 2 Small，宣称其基准测试成绩具有竞争力，并称训练全程采用 nvfp4 精度。Hacker News 讨论中，评论者认为这是迄今以该精度训练出的最强模型，并可能解释其训练速度之快。有评论指出，报告团队并非基准测试的明显赢家，这一点令人耳目一新；该模型据称优于 GLM 5.3 flash，但尚待基准之外验证。上述性能与对比数据均来自厂商公告，目前未经独立核实。

hackernews · Philpax · 11月6日 00:00 · [社区讨论](https://news.ycombinator.com/item?id=50386338)

**「背景」** 开源权重模型指权重可公开下载、供自行部署或微调的模型，与仅提供 API 的闭源模型相对。nvfp4 是英伟达提出的 4 位浮点训练与推理数值格式，相比常见的 FP8、BF16 精度更低，理论上可显著降低显存占用和计算成本，但此前少有模型以全流程该精度训练。

**「影响」** 若全 nvfp4 训练的效果在独立评测中得到确认，将降低中小团队训练高性能模型的门槛，并推动低精度训练流程的采用。

**「社区讨论」** 评论者普遍认为全 nvfp4 训练是本次发布最重要的技术点，并看好美国团队以较小资源产出有竞争力开源模型的前景。也有人提醒，基准成绩需在真实使用中验证，并称赞报告方未把自己列为明显赢家。

**标签**: `#open-weight models`, `#model training`, `#nvfp4`, `#benchmarks`, `#AI industry`

### [长江存储拟建第四座 NAND 工厂，国产设备占比目标 70%](https://www.ithome.com/1/023/467.htm) ⭐️ 7.0/10

据路透社 11 月 6 日援引知情人士消息，中国最大的闪存芯片制造商长江存储计划在武汉建设第四座工厂，预计生产公司最先进的 NAND 芯片，存储单元垂直堆叠层数将超过 300 层。知情人士称，新工厂的国产设备采购比例设定为至少 60%，力争达到 70%。工厂预计明年动工，但长江存储目前仅与供应商进行初步讨论，尚未正式下达订单。作为对比，长江存储第三座工厂预计今年晚些时候投产，中国供应商提供的设备占采购总量约 50%以上。提升国产设备采购比例有望让北方华创、中微半导体等厂商受益，新增国产设备预计集中在晶圆清洗、抛光和刻蚀等常规工艺环节。

rss · IT之家 · 11月6日 09:24

**「背景」** 长江存储是中国主要的 NAND 闪存制造商，其工厂建设进度和供应链选择受到半导体行业关注。NAND 芯片通过垂直堆叠存储单元提升容量，堆叠层数是衡量技术先进程度的关键指标之一。此前长江存储第三座工厂的国产设备占比已超过 50%，第四座工厂的目标进一步提高。

**「影响」** 若该计划推进，北方华创、中微半导体等中国设备厂商有望获得更多清洗、抛光和刻蚀设备订单，但工厂尚未下单，采购比例目标仍存在不确定性。

### [全球首台 4000 米级浮空风电系统完成城市首飞](https://www.ithome.com/1/023/399.htm) ⭐️ 7.0/10

据央视新闻报道，11 月 6 日，全球首台 4000 米级浮空风力发电系统 S4000 在湖南岳阳成功试飞，这是该类系统首次在城市场景完成放飞试验。S4000 长 67 米、宽 40 米、高 23 米，升空海拔可达 4000 米，输出电压覆盖 10 千伏至 35 千伏，设计使用寿命 20 年。系统通过充氦浮空平台将轻量化发电模块送至数千米高空，利用高空稳定风资源发电，再经系留缆绳将电力送回地面。首席架构设计师顿天瑞表示，本次重点测试接网性能，即在开启发电机的情况下是否会对电力与姿态稳定性造成干扰，并检验系统能否在市民和人群周边安全可靠飞行。该系统今年 8 月已在西北某试验基地完成 4000 米全流程验证，考核了高原、强紫外线、大温差条件下的极限适应性。

rss · IT之家 · 11月6日 08:21

**「背景」** 高空风能被视为尚未规模开发的新能源领域，具有风速高、风向稳定、风能密度大等特点。目前高空风能发电主要有两条技术路线：陆基方案将重型发电机留在地面，由翼伞、浮空器等空中组件牵引缆绳做功；空基方案则将发电机组随浮空器送上天空，在高空就地发电。S4000 属于后一种路线。

**「影响」** 此次城市试飞验证了整套浮空系统的可靠性、城市周边真实工况下的工程交付可能性以及现场快速部署能力，为后续适航取证和场景示范铺路，推动高空风力发电装备从技术验证走向产业化落地。

**标签**: `#floating wind power`, `#high-altitude wind energy`, `#energy hardware`, `#grid integration`, `#engineering test`
