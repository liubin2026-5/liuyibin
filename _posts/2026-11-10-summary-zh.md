**「背景」** 阿尔及利亚自 2016 年起限制新车进口以推动本地组装，2019 年后散件进口也被卡住，导致车队老化严重，全国约 8.4 万辆客车中车龄超 20 年的有 2.8 万辆。埃及约八成客车为本地组装，运营商偏好配件易找、成本更低的组装车。摩洛哥无燃油补贴，采购计划中纳入电动车。文章引用的出口量、占比、企业净利率等数据部分依赖券商报告和当地媒体转述，尚需交叉核实；关于本地组装替代整车出口后数据变化的判断，属于基于当前趋势的推断。

**「内容角度」** 可做角度：从阿尔及利亚“总统下令进口 1 万辆”这一单点事件切入，拆解中国客车对非出口翻倍背后的三重需求（事故替换、外汇复苏、赛事采购），并说明整车出口数字与本地组装之间的统计错位——出口量下降未必等于市场份额流失。

### [Claude Code 设置文件泄露 2539 个真实凭据](https://www.ithome.com/1/024/888.htm) ⭐️ 8.0/10

安全公司 Apiiro 的研究人员发现，超过 10 万份 Claude Code 本地设置文件被上传至公开 GitHub 仓库，其中约 1,100 份含有数据库密码、API Token、私钥或 root 登录信息等机密数据；结合 Git 历史、共享设置文件和智能体聊天记录，共识别出 1,994 个代码库中的 2,539 个真实凭据，涉及 63 个组织，包括学生团队、初创企业、软件代理商和成熟供应商，泄露内容涵盖 Azure 数据库密码、Square 生产令牌、SSH root 登录信息乃至医疗记录数据库的拥有者密码。问题根源在于 Claude Code 处理“自动执行命令”授权的方式：用户选择“是，且不再询问”后，授权规则连同命令原文（可能夹带密码、令牌或密钥）被写入本地的 .claude/settings.local.json 文件。该文件按设计应被加入全局 .gitignore，但当项目被克隆到另一台电脑，或普通文件夹后来才被初始化为 Git 仓库时，就可能被误提交；研究还称 Claude Code 有时会在未经用户确认的情况下自行提交设置文件变更，且即使原仓库删除泄露文件，已创建的 fork 仍可能保留密钥。Claude Code 团队的 Boris Cherny 于 11 月 7 日在 Hacker News 回应称团队正在研究预防措施，建议用户使用密钥扫描工具清理敏感信息，并考虑把密钥扫描功能内置到 Claude Code。

rss · IT之家 · 11月10日 08:45

**「背景」** Claude Code 是 Anthropic 推出的 AI 编程智能体，可在终端中执行 Shell 命令并读写项目文件。为减少重复确认，它提供“不再询问”的授权选项，将允许执行的命令规则持久化到项目本地的设置文件中。这类本地配置文件通常依赖 .gitignore 排除在版本控制之外，但 .gitignore 规则的作用范围与仓库初始化时机相关，容易在迁移或重新初始化仓库时失效。

**「影响」** 使用 Claude Code 并曾对含敏感参数的命令选择“不再询问”的开发者，其项目设置文件可能已进入公开仓库，需要立即轮换相关凭据并检查 fork 中的残留。

### [用电视信号穿墙感知运动的技术项目](https://maurycyz.com/projects/fading/) ⭐️ 7.0/10

开发者 MaurycyZ 发布项目文章《Your TV can see through walls》，展示如何利用普通电视广播信号实现穿墙运动感知。该项目属于射频感知与信号处理方向，通过分析环境中电视信号的变化来探测墙体另一侧的移动，并给出了具体的实现细节。文章在 Hacker News 上引发讨论，评论者将其与 LTE/4G 交通流量感知、光纤窃听等同类技术联系起来。该项目是动手探索性质的技术演示，而非产业级产品发布。

hackernews · Curiositry · 11月10日 05:24 · [社区讨论](https://news.ycombinator.com/item?id=50436410)

**「背景」** 射频感知的基本原理是：发射信号经环境中的物体反射后，接收端信号会因物体移动而发生可测量的变化，分析这些变化即可推断运动。电视广播信号长期广泛覆盖，且无需专门发射设备，因此被视为一种现成的“免费雷达”信号源。类似思路已被用于 Wi-Fi 感知和基于蜂窝网络的交通监测。

**「影响」** 这类演示说明，无需专用硬件，仅凭环境中已有的广播信号就可能实现穿墙运动探测，这对隐私边界和现有感知技术的成本门槛提出了现实问题。

**「社区讨论」** 评论者补充了多种相关技术：有人指出可通过光纤中光信号因声波引起的微小变化来窃听，但仅限单条线路；armcat 提到曾用 LTE/4G 信号系统化统计道路交通，甚至能判断行进方向和车辆类型，且因不依赖移动手机而比 Google Maps 更准确。也有人回忆模拟天线电视时代人体位置会影响信号，并推荐了《Silence on the Wire》一书及低于 10 美元的 Wi-Fi/LTE 频谱观测方案。

### [浏览器工具追踪一周内过境卫星并展示实拍影像](https://www.watched.earth/) ⭐️ 7.0/10

开发者 a585gupt 在 Hacker News 发布 Show HN 项目 watched.earth，用户输入任意地点后，该浏览器工具会基于 CelesTrak 目录用 SGP4 算法找出过去 7 天内过境该地的所有卫星，并调取这些卫星实际拍摄的 Sentinel-2、Landsat 和 NASA 影像。项目跟踪 17k+ 个在轨物体，在浏览器中约半秒完成计算，并将全部约 1.7 万个物体绘制在 GPU 上、每帧求解开普勒方程。作者指出 Sentinel-2 时间戳常与实际过境时刻相差 5-10 分钟，站点通过额外数学处理提高准确性；工具只展示来自这些卫星的真实图像，且不存储用户位置，代码已在 GitHub 开源。

hackernews · a585gupt · 11月9日 17:51 · [社区讨论](https://news.ycombinator.com/item?id=50428907)

**「背景」** SGP4 是 NORAD 开发的一种简化轨道传播模型，广泛用于根据两行轨道根数（TLE）预测卫星位置，CelesTrak 则提供公开的卫星目录数据。Sentinel-2 和 Landsat 是公开的地球观测卫星，其影像常被用于地理空间分析，但影像元数据中的时间戳与卫星实际过境时刻可能存在偏差。

**「影响」** 该工具让普通用户无需专业软件即可查询任意地点一周内的卫星过境记录并查看对应实拍影像，对地理空间从业者和卫星爱好者具有直接实用价值。

**「社区讨论」** 评论普遍称赞项目在视觉呈现与数据整合上的完成度，有用户称其可能是所见风格与实质结合最好的作品之一，地理空间从业者也认可其能展示卫星拍摄的精确影像。同时有评论指出站点文案和字体选择带有明显的 AI 生成痕迹，建议合并短句以显得更自然；一位有卫星地面处理经验的用户则建议增加地点选择器而非仅靠输入，并对比了军用系统的差异。
